# diagram-plan

Answers "what blocks what, and where are we?" Plan diagrams go wrong when
they are drawn from memory: a dependency that was never recorded, a task
already done drawn as open. So this skill does not hand-draw plans. It
generates them from Quest's own records, and the truth check re-derives
every edge.

`<engine>` is `${CLAUDE_SKILL_DIR}/../diagram-review/scripts`; shared rules
live in `${CLAUDE_SKILL_DIR}/../diagram-review/references/`.

## Workflow

### 1. Scope the question

| The reader wants | View | Command |
|---|---|---|
| What blocks what, what can start | Dependency view | `quest_graph.py deps` |
| What each milestone holds | Milestone view | `quest_graph.py milestones` |
| When things land, with real dates | Gantt | Hand-written `gantt`, only from recorded dates |

Narrow to the slice the question is about. The node cap (7, 12 or 20 by
reader level, from `levels.md`) is the point, not an obstacle. Useful
filters:

- `--open`: drop done and closed tasks ("what's left").
- `--parent <id>`: one epic's subtasks.
- `--label <label>`, `--milestone <M-n>`.
- `--ids A,B,C`: an exact set, such as one task and its prerequisites.

Use `quest task list --ready --json` to name what can start now.

### 2. Generate

```bash
python3 <engine>/quest_graph.py deps --open --level intermediate \
  --title "Open work on the diagram suite" --markdown > /tmp/plan.md
```

The output is a profile-clean Mermaid fence with:

- one node per task, labelled `ID: title (status)`;
- one arrow per recorded dependency, from the prerequisite to the task it
  unblocks;
- status shown three ways: a word in the label, a border style and a colour;
- a `%% ref` and an `%% edges: quest-dependencies` line, so
  `diagram_truth.py` can re-check every edge;
- a legend line after the fence.

Exit 3 means the slice is over the cap; narrow it, or draw one diagram per
milestone. **Do not hand-edit the generated edges.** If the plan looks
wrong, the tracker is wrong. Say so, and offer to fix the record
(`quest task edit <id> --add-dependency ...`) rather than the picture.

### 3. Check

Run the three checks in `checks.md`. For plan diagrams the truth check
compares drawn edges with Quest's `dependencies` exactly, so a stale
snapshot fails it.

### 4. Explain

Lead with the status in one sentence ("Two of nine tasks are done; the
validation gate blocks everything else"). After the diagram, name:

- what is ready to start now;
- the longest chain still open (the critical path), and what it waits on;
- anything blocked on something outside the tracker.

A beginner gets the story without task ids. An intermediate reader gets ids
with short names. An advanced reader gets the critical path, ready items and
risks. Then the legend line.

### 5. Persist, rarely

Plans change daily, so prefer regenerating to committing. If the user wants
a snapshot in a Story or Epic, date it ("as of 2026-10-05") and keep the
`%% generated by` line, so readers know to regenerate (`persisting.md`).

## What not to do

- Do not draw dependencies Quest does not record, even obvious ones; add
  them to Quest first.
- Do not draw a Gantt from guessed dates; use the dependency view.
- Do not show done work when the question is what is left.

## Reference files

From `${CLAUDE_SKILL_DIR}/../diagram-review/references/`:

- `levels.md`: caps and explanation patterns per reader.
- `truth.md`: how `%% edges: quest-dependencies` is checked.
- `accessibility.md`: status styling rules.
- `checks.md`: the parse, lint and truth loop.
- `persisting.md`: snapshots in Stories, dated.

In this skill: `examples/` holds a generated plan of this repository's own build.
