# The Mermaid profile

The subset of Mermaid every diagram-skills diagram is written in, and why.
It is pinned to the Mermaid version GitHub renders (11.17.2 on 2026-10-05),
because a diagram that parses on npm's latest but not on GitHub is broken
for most readers ([ADR-0001](../../../docs/adr/0001-use-mermaid-in-markdown-as-the-diagram-notation.md)).

## Contents

1. Allowed diagram types
2. Rules that prevent the common parse failures
3. Safe templates per type
4. Comment conventions the checks read
5. Known gaps the parser will not catch

## 1. Allowed diagram types

| Use | Header | Notes |
|---|---|---|
| Architecture (C4), flows, decisions, plans | `flowchart LR` or `flowchart TD` | Never `graph` (legacy keyword, renders differently) |
| Interactions over time | `sequenceDiagram` | |
| Lifecycles | `stateDiagram-v2` | Never plain `stateDiagram` |
| Data | `erDiagram`, `classDiagram` | |
| Dated schedules | `gantt` | Only when every date is real |
| Tiny C4 context | `C4Context` | Experimental; its parser accepts malformed input, so prefer a flowchart |

Not allowed: `-beta` types (`architecture-beta`, `block-beta`, ...),
`mindmap` (breaks with `accTitle`), `timeline`, and the `@{ shape: ... }`
syntax. They need newer Mermaid than GitHub ships, or break terminal
renderers, or both.

## 2. Rules that prevent the common parse failures

These are the documented traps, each of which the lint catches.

- **Quote every flowchart label**, nodes and edges alike:
  `api["Orders API (Node.js)"]`, `a -- "calls, HTTPS" --> b`.
  An unquoted `(`, `)`, `[`, `]`, `{`, `}` or `"` inside a label is read
  as a shape token and the diagram fails to parse.
- **No lowercase `end` as a node id.** It closes a subgraph. Use `done`.
- **No id starting with `o` or `x` straight after an arrow.**
  `a-->ops` becomes a circle-ended edge to `ps`. Put a space after the
  arrow (`a --> ops`) or rename the id.
- **Ids are plain:** letters, digits and underscores (`orders_api`,
  `DSKI_5`). Put the human name in the quoted label.
- **Sequence messages:** write a semicolon as `#59;`, and do not end a
  message with a bare `end`.
- **ER entity names with spaces** must be quoted; prefer `snake_case`.
- **Subgraphs are referenced by id, never by title:**
  `subgraph core["Core services"]` then `core --> db`.
- **Escape a double quote inside a label** as `#quot;`.

## 3. Safe templates per type

Every template already carries the accessibility fields (see
`accessibility.md`) and the comment lines the checks read (section 4).

```text
flowchart LR
  accTitle: <what the diagram shows, one line>
  accDescr: <one or two sentences: the claim, read in words>
  %% level: intermediate
  user["Reader"] -- "opens" --> docs["Docs site (MkDocs)"]
  docs -- "reads, HTTPS" --> api["Search API (Go)"]
  %% ref user = ext:People who read the docs
  %% ref docs = path:site
  %% ref api  = path:services/search
```

```text
sequenceDiagram
  accTitle: Placing an order
  accDescr: The browser posts the order, the API reserves stock, then charges the card.
  participant B as Browser
  participant A as Orders API
  participant P as Payments
  B->>A: POST /orders
  A->>P: charge(card, total)
  P-->>A: approved
  A-->>B: 201 Created
  %% ref B = ext:Customer's browser
  %% ref A = path:services/orders/api.py#create_order
  %% ref P = path:services/payments
```

```text
stateDiagram-v2
  accTitle: Order lifecycle
  accDescr: An order is placed, then paid, then either shipped or refunded.
  [*] --> placed
  placed --> paid : payment approved
  paid --> shipped : label printed
  paid --> refunded : customer cancels
  shipped --> [*]
  refunded --> [*]
  %% ref placed   = path:src/orders/states.py#PLACED
  %% ref paid     = path:src/orders/states.py#PAID
  %% ref shipped  = path:src/orders/states.py#SHIPPED
  %% ref refunded = path:src/orders/states.py#REFUNDED
```

For `erDiagram`, `classDiagram` and Quest plans, generate rather than
write: `schema_er.py` and `quest_graph.py` emit profile-clean output with
refs already attached.

## 4. Comment conventions the checks read

Mermaid ignores `%%` lines, so these cost the reader nothing.

| Line | Read by | Meaning |
|---|---|---|
| `%% level: beginner` | `diagram_lint.py` | The reader level, which sets the node cap (7 / 12 / 20) |
| `%% ref <node> = <kind>:<target>` | `diagram_truth.py` | Where the node comes from; see `truth.md` |
| `%% edges: quest-dependencies` | `diagram_truth.py` | Edges must equal Quest's `dependencies` exactly |
| `%% generated by <script>` | people | Regenerate rather than hand-edit |

## 5. Known gaps the parser will not catch

A diagram can parse and still be wrong:

- `Draft Review: submit` in a state diagram parses as two separate states,
  not a transition. Every transition needs `-->`.
- An unclosed `Person(` in `C4Context` parses.
- A flowchart edge to a misspelt id silently creates a new, unlabelled
  node. The truth check catches it, because the new node has no `%% ref`.
